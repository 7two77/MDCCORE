## Решения рабочего пакета

### 1. Поддерживаемые features

Целевые профили: `std` и `no_std + alloc`. Feature `std` включает `alloc`, поскольку
публичная модель использует динамические коллекции. Конфигурация без обоих
features получает явную диагностическую ошибку вместо каскада ошибок импортов.
Безаллокаторная реализация не входит в MDC-IMPL-001.

### 2. Владение канонической основой

`CanonicalSemanticBasis::canonical_basis()` возвращает владеющий `Vec<u8>`.
Это позволяет освобождать созданные bytes обычными средствами Rust и устраняет
необходимость в `Box::leak`.

Изменение сигнатуры является **source-breaking** для внешних реализаций trait.
Их необходимо изменить с:

```rust,ignore
fn canonical_basis(&self) -> &[u8]
```

на:

```rust,ignore
fn canonical_basis(&self) -> Vec<u8>
```

Возвращаемый буфер принадлежит вызывающему коду. Для `no_std` тип импортируется
из `alloc::vec::Vec`. Код, уже вызывающий `.to_vec()` на результате, может убрать
дополнительное копирование.

### 3. Совместимость существующих identity

В этом пакете сохраняются существующие bytes Observation, полученные через
`Debug`-форматирование source ID, timestamp и payload, а также существующий
протокол `core::hash::Hash` с FNV-подобным `u64` hasher. Это позволяет исправить
владение памятью без одновременной неявной миграции identity.

Это временная совместимость с исходной реализацией. Она **не обещает** стабильный
формат между платформами или версиями Rust, криптографические свойства либо
отсутствие коллизий. Формат переносимой канонизации, её версия и collision policy
должны быть определены следующим контрактным решением.

### 4. Snapshot и согласованность identity/content

Один snapshot получает canonical basis ровно один раз и вычисляет identity из
того же сохранённого буфера. Это предотвращает рассогласование при реализации
trait с внутренней изменяемостью.

Текущий `Snapshot` фиксирует существующую identity basis. Полный audit snapshot
будущего графа может включать дополнительные поля provenance, context и status.
Их включение в audit snapshot не делает их автоматически identity-defining.
Полный audit snapshot MDC-01…06 в этом пакете не реализуется.

### 5. Граница conformance

Общие механизмы reference/contract resolution, трёхзначная агрегация, полноценная
provenance и операции MDC-02…06 ещё требуют реализации. Существующие E2E-тесты
не объявляются полным gate и не получают недостающие алгоритмы внутри fixture.

`NOT_EXECUTED` относится к test harness; это не semantic result `UNRESOLVED`.
Полный MDC-E2E-CONFORMANCE-001 остаётся **NOT EXECUTED / BLOCKED**.

## Проверки

Следующие команды предназначены для активного корневого пакета. При необходимости
`CARGO_TARGET_DIR` указывается снаружи, чтобы размещать build artifacts отдельно.

```bash
cargo test --locked --offline
cargo test --locked --offline --features std,alloc
cargo test --locked --offline --no-default-features --features alloc
cargo check --locked --offline --no-default-features --features alloc
cargo fmt --check
cargo clippy --locked --offline --all-targets -- -D warnings
cargo clippy --locked --offline --no-default-features --features alloc --all-targets -- -D warnings
```

Отдельно ожидается отказ неподдерживаемого профиля:

```bash
cargo check --locked --offline --no-default-features
```

Такой отказ считается ожидаемым результатом только при явном сообщении об
обязательном `alloc`, а не при случайных ошибках типов или импортов.

Регрессии должны проверять одно получение basis на snapshot, соответствие
identity сохранённым bytes, сохранение исходного представления Observation,
владение результатом после уничтожения Observation и освобождение памяти после
повторных операций. Эти проверки не заменяют полный conformance fixture.

## Следующий функциональный результат

Реализовать admission Observation с разрешением source/schema/context и provenance,
затем Measurement с зарегистрированным оператором, версией, ordered inputs и units.
Критерий завершения — воспроизводимая цепочка **Source → Observation → Measurement**
с положительными и отрицательными проверками и трассировкой до источника.
